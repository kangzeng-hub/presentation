# Presentation System 业务汇报结构说明

## 汇报主线

Presentation System 被定位为“SKU 内容生产与决策系统”：围绕一个 SKU 统一产品事实、竞品输入、消费者问题与内容策略，再驱动 Listing、图片和视频等内容资产。当前项目真实能力以图片策略/生成/校准为主，Listing 统一工作区与视频工作区仍在建设，因此 PPT 对已实现、建设中和规划能力做了明确区分。

## 使用原则

- 不把技术实现名词当作汇报主角；技术只在证据说明中出现。
- 不使用未经项目验证的节省工时、ROI、自动化比例或无人值守结论。
- “视频”在 PPT 中只表达当前已有的 Prompt 构建和生成请求能力；完整视频工作区列为建设中。
- “Listing”在 PPT 中表达目标链路与建设方向；当前仓库没有统一 Listing 生成/编辑服务，不能写成已完成。

## 第二轮重构补充

第二轮将叙事重构为：业务输入 → 业务判断 → 系统决策 → 内容执行 → 业务校正 → 经验沉淀。新增页面覆盖决策链总图、产品理解、竞品研究、消费者问题、内容策略、图片策略、真实 SKU 案例、QA 校正闭环与业务主管可直接管理的决策点。

本轮使用的真实案例是 G23Studio ASTM F136 铰链鼻中隔环 3 件套：产品图来自 `p1/p1.jpg`，竞品样本来自 `c1/`、`c2/`，六项购买问题与优先级来自 `image_plan.json`，结果校正证据来自 `output/wan_baseline_v1/qa/qa_summary.json` 与 `calibration/*`。

## 第四轮调整：前半段改为双向逻辑

前 5 页不再按“系统介绍 / 模块介绍”划分，而是集中讲一条双向链：

- **0 → 1**：SKU / 产品资料 / 产品图片 / 竞品链接与评论 → 产品事实、竞品差异、消费者问题 → 内容策略 → Listing / 图片 / 视频。
- **1 → 0**：内容产出 → 业务审核 → 识别事实、任务、证据或表达偏差 → 修改卖点优先级、图片任务、Prompt 约束 → 再生成、QA、经验沉淀。

前 5 页标题已改为：

1. 一个 SKU，先被理解，再被生产；产出之后，再被校正
2. 0 → 1：把分散的业务输入，收敛成一个“应该怎么卖”的判断
3. 0 → 1 的核心：每向下一步走一次，就做出一个业务决策
4. 1 → 0：内容结果不是终点，而是反向检验业务判断
5. 一个完整闭环：从 0 到 1，再从 1 回到 0

后续模块页与真实 SKU 案例页保留，用于解释这条双向逻辑在产品理解、竞品分析、Listing、图片、视频和人工校正中的具体落点。

## 第五轮补充：竞品比对结果与模板抽象

在第 4 页与闭环页之间插入新的第 5 页：

**竞品比对的结果，不是“模仿谁”，而是抽象市场已经验证的表达任务。**

页面使用 `c1/`、`c2/` 真实竞品素材，提炼出：产品分组/白底（解决产品识别）、近景/尺寸对比（解决规格选择）、结构示意/细节网格（解决使用与信任）、三联风格/场景图（解决风格投射）。右侧对应映射到项目已有模板：`PRODUCT_IDENTITY_MAIN`、`CONTENTS_SET`、`SIZE_CHOICE_PROOF`、`MATERIAL_EVIDENCE`、`STRUCTURE_USE_DETAIL`、`WEAR_STYLE_TRIPTYCH`。

该页明确约束：模板只抽象构图、信息层级与消费者问题；产品形状、数量、claims 和品牌表达仍由我方 ProductTruth 与业务策略决定。当前 PPT 共 22 页。

第 5 页进一步改为具体推导例子：使用真实竞品 `c1/s2.jpg`（四宫格鼻部近景，7mm/8mm/9mm/10mm 标签），按“画面事实 → 可推断问题 → 推断依据 → 我方 ProductTruth → ImagePlan 输出”解释如何得到消费者关注点。最终落到我方 `SIZE_CHOICE_PROOF`：18G/20G、8mm 与适用位置先解决规格选择，但不从竞品图或我方水平产品图擅自推断佩戴比例。

## 第六轮调整：内容策略页改为完整因果链

原第 9 页“内容策略”过于概括，现改为以真实 G23Studio 3 件套为例的执行链：

`产品事实 → 竞品对比 → 消费者问题 → P0/P1/P2 优先级 → 标题/五点/描述/图片/视频的具体表达任务 → 业务确认点`。

页面明确：P0 先解决产品识别、套装内容、规格选择；P1 再补材质、结构、风格；P2 生活方式后置。并展示这些判断如何分别落到 Listing 标题、五点、产品描述、六张图片任务和视频动作顺序，说明为什么这样排、如何执行，而不是只列模块名称。
